# 协作房间

「对话」由 dsh-cloud 镜像中的原生 Web 前端补丁和宿主插件组成，适配 dsh `0.2.2-alpha.3`。机器人有持久的名字、头像和职责。一个机器人最多有一条私聊，也可以参加多个群聊；私聊和每个群里的执行会话及上下文分别存储。

## 开始使用

1. 重新构建镜像并重启目标工作空间。网关 schema 6 会把插件下发给默认组；其他用户组可以在管理后台分配「协作房间」。进入 DSH 后点左侧 **对话**，需要回到原来的项目列表时点 **工作区**。
2. 点列表上方 **＋**，创建 Bot 时选头像、输入名字和职责，会自动打开私聊；直接发消息即可。再从 **＋ → 新建群聊** 输入群名并勾选成员。可在群设置里调整成员和所用项目。
3. 在群里输入 `@` 选择机器人。例如发 `@调研员 请整理 inputs/ 的关键证据`，再请 `@审阅员` 核对。用 `@all` 让所有成员并行回答。Enter 发送，Shift+Enter 换行。未点名的群消息只进入聊天记录。

从列表一行右侧的 **… → 删除会话** 可删除私聊或群聊及其对话记录。私聊删除后，Bot 仍可在群里使用，也可从 **＋** 重新开启空白私聊。群聊删除不会影响同一 Bot 的私聊。项目文件与 DSH 原生执行记录保留。若要删除 Bot 身份，可在私聊设置里操作；它会退出所有群，群里的旧消息仍可查看。

点成员旁边的 **查看执行会话**，可以检查 DSH 工具调用、处理交互请求或修改该执行会话的模型。这些执行会话不会出现在普通工作区列表里。机器人的职责是工作提示，工具权限仍由 DSH 的会话预设和沙箱决定。

点房间右上角的侧栏按钮，可以打开和普通会话相同的 DSH 右侧栏。机器人开始操作工作空间浏览器时，房间会自动打开「远程浏览器」标签。每个机器人的回复有独立的底色，保留原生 Markdown 渲染。

在 **房间成员与设置 → 开启新上下文** 确认后，房间会保留聊天记录、成员和项目。下次点名时，机器人会创建新的原生会话，且提示词只包含分隔线之后的房间消息。这不会删除原生旧会话或项目文件。需要重置时先等当前批次完成，或停止当前批次。

## 运行方式

- 镜像构建修改 DSH 发布包中的 Chat、Conversation、Sidebar、Workspace 和 Right Sidebar 模块，复用原生 Markdown、消息气泡、Lexical 输入编辑器、弹窗、文件预览和工作区列表。每条对话有独立的原生右侧栏状态；远程浏览器依然使用工作空间共用的 Chromium。私聊和群聊当前支持文本；需要文件附件、完整工具轨迹或处理授权时，可进入机器人的原生执行会话。
- 宿主插件通过 DSH 自己的认证连接注册房间接口，用原生会话控制器创建会话、提交提示、停止轮次，并订阅该轮的原生流式文本和完成事件。浏览器显示共用时间线，机器人会在提示中看到房间最近的发言。一个机器人的回复里的 `@名字` 不会触发新的任务。
- Agent Teams 是另一套会话内委派系统，使用 `agentTeams` 服务管理 Lead、队友、消息和任务板。房间没有依赖该服务，也不调用 `spawn_teammate`；点名和成员管理是房间自己的逻辑。启用 Agent Teams 不会把房间成员变成同一支 Team。
- 私聊、群聊、成员、机器人和时间线保存在 `$DSH_HOME/workspace-rooms/state.json`；执行会话由 DSH 按原有方式存储。此前显示的群聊会迁入列表，旧的 `archivedRooms` 继续保留；现有 Bot 自动获得一条空白私聊，不会复制群聊记录。每条对话保留最近 200 条消息或约 400 KiB 的时间线，以先达到的限制为准。
- 每房间最多 4 位机器人；同一个用户的沙箱最多并行运行 4 位房间机器人。每个房间一次处理一批点名，可停止当前批次。等待时间最长 3 分钟。重启后房间会保留历史，未完成的房间轮次显示为中断，房间不会自动重发。
- 房间限于当前用户；它们不跨登录账号共享。机器人共用房间所选项目的文件与工作空间浏览器，同时操作时请分配不同的文件或安排先后顺序。

在仓库根目录运行 `node --test sandbox-image/tests/workspace-rooms.test.mjs`，可验证私聊和群聊隔离、会话删除、迁移、定向发送、上下文重置和中断恢复。
